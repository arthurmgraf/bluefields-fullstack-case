## Context

The CodeMap Hotel is a real-time pixel-art visualization rendered on an HTML5 Canvas using React 18.
All drawing happens in a single `requestAnimationFrame` loop inside `HabboRoom.tsx` (~1239 lines).

**Root causes of pixelation (in priority order):**

1. **Missing devicePixelRatio scaling (primary cause)**
   - File: `codemap-tool/client/src/components/HabboRoom.tsx`, lines 1046-1049
   - `canvas.width = window.innerWidth` sets buffer in CSS pixels
   - On Retina/HiDPI (dpr=2), the browser upscales a 1x buffer to 2x screen pixels = blurry
   - Fix: set `canvas.width = window.innerWidth * dpr`, then `ctx.scale(dpr, dpr)` so all drawing code stays in logical pixels
   - All canvas coordinate references (`canvas.width / 2`, `canvas.height / 2`) must use logical dimensions (`logicalW`, `logicalH`)

2. **`imageRendering: 'pixelated'` CSS on the canvas element (line 1234)**
   - Forces nearest-neighbor scaling, which is correct for pixel art but at low DPR creates harsh pixel edges
   - After fixing DPR, the canvas already renders at native resolution — this CSS becomes counterproductive for UI elements (text, bubbles)
   - Fix: remove `imageRendering: 'pixelated'` or change to `imageRendering: 'auto'`

3. **`imageSmoothingEnabled` never configured**
   - Context created with `{ alpha: false }` but smoothing never set
   - For the pixel art floor tiles and sprites, `imageSmoothingEnabled = false` is appropriate
   - For text and vector shapes, smoothing is already handled by the 2D canvas engine (not affected)
   - Fix: explicitly set `ctx.imageSmoothingEnabled = false` after getting context (maintains intentional pixel-art look at correct resolution)

4. **Font sizes too small for readability (secondary quality issue)**
   - Agent name labels: `bold 10px monospace` (agent.ts line 159)
   - Model labels: `8px monospace` (agent.ts line 179)

   - Fix: increase font sizes by +2px across all text rendering calls for better readability

## Notes

**Why `ctx.setTransform` instead of `ctx.save/scale`:**
Using `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)` at the top of each render frame resets the transform matrix cleanly before any drawing. This avoids transform accumulation across frames. The render loop already uses `ctx.save()/ctx.restore()` for zoom/pan — the DPR transform should be applied before those, establishing the base coordinate system.

**Why NOT increase TILE_SIZE:**
TILE_SIZE=16 is embedded throughout all drawing functions (furniture, tiles, room, decorations) via hardcoded pixel offsets relative to TILE_SIZE multiples. Changing TILE_SIZE would require rescaling every pixel art element individually. The DPR fix achieves the same visual improvement without touching the art data.

**Event handler coordinate correctness:**
Mouse/wheel event positions come from `e.clientX/clientY` and `canvas.getBoundingClientRect()` — these are always in CSS logical pixels. The coordinate conversion math in `handleWheel` and `handleClick` correctly uses `canvas.width/2` AS CSS pixels (since the canvas CSS size is `window.innerWidth`). After the fix, `canvas.clientWidth = window.innerWidth`, so `canvas.clientWidth / 2` is equivalent. No change needed in event handlers.
